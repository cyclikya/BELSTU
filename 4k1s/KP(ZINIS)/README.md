# Текстовая стеганография: перемежение и помехоустойчивое кодирование

Программное средство к курсовому проекту по дисциплине «Защита информации и
надёжность информационных систем».

**Тема:** Программная реализация метода на основе совместного применения
перемежения и помехоустойчивого кодирования в текстовой стеганографии.

БГТУ, факультет информационных технологий, кафедра ИСиТ.
Специальность 6-05-0611-01, курс 4, группа 1.

## Что делает программа

Помещает служебное сообщение (например отметку о номере копии документа)
внутрь обычного текста так, что видимая часть документа не изменяется, и
восстанавливает это сообщение после того, как документ был отредактирован.

Устойчивость к повреждениям обеспечивается двумя механизмами, применяемыми
совместно:

- **помехоустойчивый код** — расширенный код Хэмминга (8,4) с минимальным
  кодовым расстоянием d_min = 4, исправляет одну ошибку в блоке и
  обнаруживает две;
- **перемежение** — блочный перемежитель глубины d, распределяющий пакетное
  повреждение по разным кодовым словам.

Теоретический предел исправляемого пакета: `B_max = d · t`, где t = 1.

## Конвейер

```
ВСТРАИВАНИЕ
  сообщение → байты → заголовок (длина, версия, глубина, CRC-16)
            → код Хэмминга (8,4) → блочное перемежение
            → кадрирование синхромаркерами → символы нулевой ширины

           ↓ [ смена оформления · правка · пересохранение ] ↓

ИЗВЛЕЧЕНИЕ
  стеготекст → чтение символов нулевой ширины → поиск синхромаркеров
             → деперемежение → синдромное декодирование
             → проверка CRC → сообщение либо отказ
```

Структура потока:

```
[маркер][заголовок: код, без перемежения]
[маркер][кадр 1][маркер][кадр 2]…[маркер][кадр M]
```

Кадр — 32 кодовых слова (256 бит канала, 128 бит данных). Размер кадра не
зависит от глубины перемежения: иначе доля служебных бит различалась бы
между режимами и сравнение их в экспериментальной части было бы некорректным.

## Метод встраивания

Биты кодируются служебными символами Unicode нулевой ширины, размещаемыми
перед межсловными пробелами:

| Символ | Код | Значение |
|---|---|---|
| ZERO WIDTH SPACE | U+200B | `00` |
| ZERO WIDTH NON-JOINER | U+200C | `01` |
| ZERO WIDTH JOINER | U+200D | `10` |
| WORD JOINER | U+2060 | `11` |

Одна позиция несёт 2 бита. Вместимость контейнера `C = N · 2`, где N — число
межсловных пробелов. На странице А4 (≈ 350 слов) это 700 бит канала, то есть
около 32 байт полезной нагрузки после кодирования и кадрирования.

## Работа с программой

Интерфейс состоит из трёх вкладок.

**«Встраивание».** Загрузить текст-контейнер (кнопка «Взять пример»
подставляет текст из `data/containers/sample_ru.txt`), ввести сообщение,
выбрать глубину перемежения и нажать «Встроить сообщение». Под полем
контейнера отображается вместимость и требуемый объём. Флажок «Показать
скрытые символы» выводит встроенные символы видимыми обозначениями —
в обычном режиме стеготекст от контейнера не отличается.

**«Извлечение».** Загрузить документ либо перенести результат кнопкой «Взять
результат встраивания» и нажать «Извлечь сообщение». Выводится
восстановленное сообщение, заключение о целостности, прочитанные из
заголовка параметры и статистика блоков.

**«Устойчивость к помехам».** Задать длину пакета ошибок и выполнить прогон.
Программа встраивает одно и то же сообщение со всеми допустимыми глубинами,
вносит одинаковый пакет ошибок и показывает, при какой глубине сообщение
восстанавливается. Результат сопоставляется с теоретическим предсказанием
`B_max = d · t`.

### Кодировка файлов

Файлы читаются и записываются **только в UTF-8**. Это обязательное условие:
в однобайтовых кодировках, применяемых на русской версии Windows по
умолчанию, символы нулевой ширины не представимы, и сохранение стеготекста
уничтожило бы скрытое сообщение.

## Структура проекта

```
src/textsteg/
├── api.py              прикладной интерфейс: embed() и extract()
├── errors.py           иерархия исключений
├── core/               ядро метода, работает только с битами
│   ├── bits.py         преобразования байтов и битов
│   ├── hamming.py      расширенный код Хэмминга (8,4), SEC-DED
│   ├── interleaver.py  блочный перемежитель
│   ├── framing.py      заголовок, CRC-16, синхромаркеры
│   └── pipeline.py     сборка конвейера, кадры, ресинхронизация
├── embedding/          методы встраивания
│   ├── base.py         общий интерфейс
│   └── zerowidth.py    символы нулевой ширины
├── gui/                графический интерфейс (PySide6)
└── research/           экспериментальные исследования
tests/                  модульные и сквозные испытания
data/containers/        примеры текстов-контейнеров
```

Ядро не зависит ни от графического интерфейса, ни от методов встраивания:
метод можно исследовать независимо от способа размещения бит в тексте.

## Формат контейнера

Программа работает с неформатированным текстом (UTF-8). Поддержка
форматов с разметкой не предусмотрена намеренно.

Метод встраивания размещает данные в последовательности символов текста,
а не в его оформлении: биты кодируются служебными символами Unicode,
принадлежащими содержимому документа. Шрифт, кегль, начертание, цвет и
межстрочный интервал на скрытую последовательность не влияют и при её
извлечении не используются. Поэтому разметка не добавляет методу ни новых
возможностей, ни новых видов повреждений, а неформатированный текст
является достаточной и адекватной моделью контейнера.

Сфера применимости при этом не ограничивается файлами .txt: метод
применим к любому формату, сохраняющему символьное содержимое документа
без очистки служебных символов.
