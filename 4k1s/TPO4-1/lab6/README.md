# Лабораторная работа 6 — автоматизация UI-тестирования

Сайт для тестирования: **demoqa.com**. Язык — Python, Selenium 4 и pytest,
браузер Chrome. Драйвер скачивать не нужно: Selenium 4 подбирает его сам.

## Установка

```powershell
pip install -r requirements.txt
```

## Запуск

```powershell
python lab06_1.py
pytest -v lab06_2.py
```

## lab06_1 — задание 1

Программа открывает браузер, загружает demoqa.com и находит элементы пятью
способами, печатая по каждому тег и содержимое.

| Способ | Что ищем |
|---|---|
| `By.ID` | поле `firstName` на форме практики |
| `By.NAME` | группа переключателей пола `gender` — три радиокнопки |
| Составной CSS №1 | `form#userForm input#userEmail` — поле почты внутри формы |
| Составной CSS №2 | `#userForm div.form-check label.form-check-label[for='hobbies-checkbox-1']` — подпись чекбокса |
| Составной XPath №1 | `//form[@id='userForm']//input[@id='userNumber']` — поле телефона внутри формы |
| Составной XPath №2 | от чекбокса вверх по оси `ancestor` до его блока и обратно вниз до подписи |
| `By.PARTIAL_LINK_TEXT` | ссылки по фрагментам «Text Box» и «Web Tables» |
| `find_elements` → список | пункты меню раздела Elements и все ссылки страницы |

Второй XPath сделан через ось `ancestor` специально: так проверяется, что
подпись принадлежит именно тому чекбоксу, с которого начали. Через CSS так не
получится — у него нет перехода к предку.

## lab06_2 — задание 2

Пять тестов, по числу пунктов задания.

| Тест | Что проверяет |
|---|---|
| `test_login_with_invalid_credentials` | авторизация: при неверных данных выводится «Invalid username or password!», перехода в профиль не происходит |
| `test_text_box_form_submission` | форма Text Box: отправленные данные выводятся в блоке результата |
| `test_web_tables_add_record` | добавление записи в Web Tables и её появление в таблице |
| `test_end_to_end_web_tables` | сквозной сценарий: создание записи → поиск → изменение зарплаты → удаление |
| `test_select_dropdown_and_checkbox` | выпадающий список, список с множественным выбором, чекбокс и радиокнопка |

Проверка авторизации сделана негативной намеренно. Положительный вход требует
учётной записи, а регистрация на demoqa закрыта: вместо чекбокса «я не робот»
страница показывает невидимый бейдж reCAPTCHA, отметить нечего, и форма
отвечает «Please verify reCaptcha to register!». Зарегистрироваться там
невозможно даже вручную. Негативная проверка от этого не теряет смысла: она
тоже заканчивается сравнением фактического результата с ожидаемым.

Сквозной сценарий построен на Web Tables, потому что весь цикл «создать —
найти — изменить — удалить» там выполняется без входа в систему.

## Ожидания

Используются оба вида:

- **неявное** — `driver.implicitly_wait(5)` в фикстуре, действует на все
  вызовы `find_element` в течение сессии;
- **явное** — `WebDriverWait(driver, 15)` с условиями из `expected_conditions`
  в каждом тесте: видимость элемента, кликабельность, готовность документа,
  появление строки в таблице, исчезновение удалённой записи.

Каждый тест завершается сравнением фактического результата с ожидаемым.

## Замечания по сайту

**Таблицу Web Tables переделали.** В старых примерах она размечена как
ReactTable с классами `rt-tbody` и `rt-tr-group`. Сейчас это обычная
bootstrap-таблица, поэтому строки ищутся как
`div.web-tables-wrapper table tbody tr`. Код из старых руководств на этой
странице работать не будет.

**Внизу страниц висит рекламный блок.** Он перехватывает клики по элементам,
оказавшимся под ним, поэтому нажатия идут через вспомогательную функцию
`click`: она сначала прокручивает элемент в центр экрана, а при перехвате
повторяет нажатие через JavaScript.

**Каждый тест запускает свой браузер.** Тесты не делят состояние: иначе
запись, оставленная упавшим тестом, роняла бы следующий.
