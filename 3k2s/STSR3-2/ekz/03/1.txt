//1 Протокол HTTP: общие свойства, версии и их особенности.

Создатель HTTP и HTML – Тим Бёрнерс-Ли (Также он глава W3C).

HTTP – полудуплексный протокол прикладного уровня по кот общаются клиент и сервер, он описывает правила общения

Версии HTTP:
    1. 0.9 (Работает поверх TCP. Только гипертекст (нельзя передавать файлы). Нет заголовков, status codes, полного URL.  Methods: GET)
    2. 1.0 (Есть кеширование, аутентификация, заголовки (e.g. Content-Type), можно передавать медиа (фото, видео, аудио), есть коды ответа. Нет постоянного соединения.  Methods: GET, HEAD, POST)
    3. 1.1 (Действующая версия. Имеет постоянное соединение (Connection: keep-alive), есть SSL/TLS, chunked responses)
    4. 2.0 (Не распространен. Есть параллельные запросы в рамках одного соединения и сжатие одинаковых заголовков. Бинарный: (это значит, что в 2.0 всё изначально закодировано и сжато, а в 1.1 изначально всё в строковом значении, а только потом сжимается))
    5. 3.0 (Не распространен. Главная особенность – универсальный транспортный протокол QUIC, работающий поверх UDP. Замена TCP)

HTTP: основные свойства
  - версии HTTP/1.1 – действующий (текстовый), HTTP/2 – черновой (не распространен, бинарный);
  - два типа абонентов: клиент и сервер;
  - два типа сообщений: request и response;
  - от клиента к серверу – request;
  - от сервера к клиенту – response;
  - на один request всегда один response, иначе ошибка;
  - одному response всегда один request, иначе ошибка;
  - TCP-порты: 80, 443(HTTPS);
  - для адресации используется URI или URN;
  - поддерживается W3C, описан в нескольких RFC.
  - HTTP:  RFC2616

HTTPS (HTTP + SSL/TLS) – специальный протокол, обеспечивающий шифрование и аутентификацию.
  SSL – Secure Socket Layer, был заменен в 2014 на TLS
  TLS – Transport Layer Security
  

//3. Пакет Express. Основные принципы работы. Выполнение js-скриптов в отдельном процессе (fork, send, worker). Пример.

Express — это фреймворк (пакет npm) для Node.js, который упрощает создание веб-сервера. Если на голом модуле http маршрутизацию и разбор запроса приходится писать руками, то Express даёт это «из коробки».

Промежуточное ПО (Middleware) — это функции, которые имеют доступ к объекту запроса (req), объекту ответа (res) и следующей функции промежуточного ПО в цикле "запрос-ответ" приложения. Следующая функция промежуточного ПО обычно обозначается переменной next.

Основные принципы работы (по лекции):
    - Подключение и запуск. 
        Подключается через require('express'),
        создаётся приложение const app = express(), 
        запускается методом app.listen(порт). 
        Остановка — server.close().
    - Маршрутизация (routing). 
        Каждому HTTP-методу соответствует свой метод приложения: app.get(), app.post(), app.put(), app.delete(). 
        В них указывается путь и функция-обработчик. То есть маршрут = метод + путь + обработчик.
    - Объекты request и response. 
        В обработчик передаются два объекта: 
            request (запрос — со своими свойствами и методами, например req.query)
            response (ответ — методы res.send(), res.end() и др.). 
        Через них читают запрос и формируют ответ.
    - Middleware и конвейер. 
        Главный принцип Express — обработка запроса идёт через конвейер из middleware (промежуточных обработчиков). 
        Каждый middleware получает request, response и функцию next; сделав свою работу, он вызывает next(), передавая запрос следующему звену. 
        Это позволяет разбить обработку на independent модули (логирование, аутентификация и т.д.).

Выполнение js-скриптов в отдельном процессе (fork, send, worker)
  В чём идея fork: Node.js по своей природе однопоточный. Если в обработчике запустить тяжёлое вычисление, оно «заморозит» весь сервер — другие запросы будут ждать. 
  Решение: вынести тяжёлую работу в отдельный процесс (worker), который считает параллельно, не блокируя основной сервер.

  fork, worker, send, message — четыре связанных понятия
    - fork — функция из child_process, которая запускает новый Node.js-процесс из указанного .js-файла. По сути это особый случай spawn, заточенный именно под Node.js-скрипты.
    - worker — это и есть тот самый отдельный скрипт (рабочий процесс), который запускают через fork. Он делает свою задачу (например, вычисления) отдельно от основного сервера.
    - send и message — это канал связи между основным процессом и worker'ом. Главная фишка fork: между процессами автоматически создаётся связь, по которой они обмениваются сообщениями:

  send(сообщение) — отправить сообщение другому процессу;
  событие 'message' — принять сообщение (process.on('message', ...) или worker.on('message', ...)).

  То есть основной сервер через send «говорит» worker'у задачу, а worker через send возвращает результат, и сервер ловит его на событие 'message'.


  Как это работает (по примеру)
    Основной файл (server.js): Express, создаёт worker через fork, и на запрос отправляет ему данные:
            const { fork } = require('child_process');
            
            const worker = fork('./worker.js');   // запустили отдельный Node.js-процесс

            app.get('/calc', (req, res) => {
              const a = Number(req.query.a);
              const b = Number(req.query.b);

              worker.send({ cmd: 'add', a, b });        // отправили задачу worker'у

              worker.once('message', (msg) => {          // ждём ответ от worker'а
                res.json({ a, b, sum: msg.result });     // отдали результат клиенту
              });
            });
    Файл worker'а (worker.js): принимает сообщение, считает, отправляет результат обратно:
            process.on('message', (msg) => {            // получили задачу от сервера
              if (msg.cmd === 'add') {
                process.send({ result: msg.a + msg.b }); // отправили результат обратно
              }
            });
    Цепочка: клиент → сервер send задачу → worker считает → worker send результат → сервер ловит message → ответ клиенту.
    
    Отличие fork от spawn и exec (это спросят!)
      spawn / exec — запускают команды операционной системы (ls, echo, date).
      fork — запускает отдельный Node.js-скрипт (.js-файл) и добавляет канал обмена сообщениями (send / message), которого у spawn/exec нет.
