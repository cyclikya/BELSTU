//1 Структура HTTP-запроса.

HTTP-запрос (request) — это текстовое сообщение, которое клиент отправляет серверу. У него есть строгая структура из нескольких частей, идущих в определённом порядке

Из чего состоит запрос
1. Стартовая строка (request line). Самая первая строка запроса. Состоит из трёх элементов:
    метод + URI + версия протокола
    Пример: GET /smelov HTTP/1.1
        GET — метод (что хотим сделать),
        /smelov — URI (адрес ресурса, к которому обращаемся),
        HTTP/1.1 — версия протокола.
    Это «шапка» запроса — по ней сервер сразу понимает, что от него хотят и по какому адресу.
2. Заголовки (headers). Идут после стартовой строки. Это набор пар (имя: значение), которые несут метаинформацию о запросе — например, какой формат данных ожидается, какой хост, какие cookie и т.д. Заголовков может быть много.
3. Параметры: Отдельный важный момент — параметры запроса можно передавать тремя способами:
        В query string — после знака ? в адресе: /parameter?x=1&y=2. Пары имя=значение.
        В самом URI (в пути) — параметры встроены прямо в путь: /parameter/1/2.
        В теле запроса — данные лежат в body (характерно для POST/PUT).
    То есть один и тот же параметр можно передать по-разному, и сервер достаёт его из нужного места в зависимости от способа.
3. Тело запроса (body). Это сами данные, которые клиент передаёт серверу. Тело есть не у всех запросов: например, у GET его обычно нет, а у POST и PUT именно в теле едут передаваемые данные (например, JSON или содержимое формы).

Методы запроса (request methods)
Метод — это то, что стоит в начале стартовой строки; он говорит, какое действие клиент хочет выполнить. Сначала отвечай кратко перечислением, а если попросят — раскрывай:
    GET — получить информацию (ресурс) по указанному URI.
    POST — отправить данные на сервер; сервер принимает их как новый подчинённый ресурс. Основной метод для загрузки информации на сервер.
    PUT — создать новый ресурс или заменить (обновить) существующий данными из тела запроса.
    DELETE — запросить удаление ресурса по URI.
    HEAD — то же, что GET, но сервер возвращает только заголовки, без тела ответа (только метаинформация).
    OPTIONS — запрос информации о доступных способах связи с сервером (какие методы/возможности поддерживаются).
    CONNECT — запускает двустороннюю связь, используется для открытия туннеля.
    TRACE — проверка обратной связи по пути к ресурсу, механизм отладки (сервер отражает полученное сообщение обратно).
    PATCH — частичное изменение ресурса.

Дополнительно (говорить только если спросят!): 
существует протокол WebDAV, добавляющий ещё 7 методов: 
PROPFIND, PROPPATCH, MKCOL, COPY, MOVE, LOCK, UNLOCK.
