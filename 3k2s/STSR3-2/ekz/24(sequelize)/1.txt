//1. Разработка простейшего HTTP-сервера в Node.js. Извлечение данных из HTTP-запроса, формирование данных HTTP-ответа.  Пример. Тестирование с помощью браузера AJAX (XMLHTTPRequest/Fetch). 

1. Что такое HTTP-сервер в Node.js
    В Node.js есть встроенный модуль http — он позволяет создать веб-сервер без сторонних пакетов. Сервер создаётся методом http.createServer(), которому передают функцию-обработчик. Эта функция вызывается на каждый входящий запрос и получает два объекта:
        - request (req) — входящий запрос (всё, что прислал клиент);
        - response (res) — ответ (то, что сервер отправит обратно).
    Запускается сервер методом listen(порт) — он начинает «слушать» указанный порт и ждать запросы.
    Главная идея: сервер — это обработчик, который на каждый запрос получает пару «req — res»: из req читает данные, в res формирует ответ.

2. Извлечение данных из HTTP-запроса
    Это первая половина вопроса. Из объекта request можно достать разные части запроса:
    Метод и адрес:
        req.method — HTTP-метод (GET, POST, PUT, DELETE);
        req.url — адрес запроса (путь + строка запроса).

    Параметры из строки запроса (query).
    Адрес вида /search?term=apple разбирают встроенным модулем url: метод url.parse(req.url, true) отделяет путь (pathname) от параметров (query).
    
    Заголовки:
        req.headers — объект со всеми заголовками запроса.
    
    Тело запроса (body). 
    Самое важное и нетривиальное. Тело (например, у POST) приходит не сразу, а по частям (кусками) — потому что req это поток. Поэтому его собирают через два события:
        - событие data — срабатывает на каждый пришедший кусок (его накапливают в строку);
        - событие end — срабатывает, когда тело получено целиком (тогда строку можно разобрать, например JSON.parse).
    То есть нельзя прочитать тело одной строкой — надо «слушать» поток, пока он не закончится.

3. Формирование данных HTTP-ответа
    Это вторая половина. Ответ собирают через объект response:
        - код состояния — res.statusCode = 200 (или 404 и т.д.);
        - заголовки — res.setHeader('Content-Type', 'application/json') — сообщаем клиенту формат ответа;
        - тело и отправка — res.end(данные) — записывает тело и завершает ответ (без end клиент будет ждать вечно).
    Если данные — это объект, его сериализуют в строку: res.end(JSON.stringify(объект)).

4. Маленький пример (как иллюстрация к теории)
        const http = require('http');
        const url = require('url');

        const server = http.createServer((req, res) => {
        const parsed = url.parse(req.url, true);   // разбираем адрес

        // извлекаем данные из запроса: метод, путь, параметр
        if (req.method === 'GET' && parsed.pathname === '/hello') {
            const name = parsed.query.name || 'гость';   // параметр из query

            // формируем ответ
            res.statusCode = 200;
            res.setHeader('Content-Type', 'application/json; charset=utf-8');
            res.end(JSON.stringify({ message: 'Привет, ' + name }));
        } else {
            res.statusCode = 404;
            res.end('Не найдено');
        }
        });

        server.listen(3000);
    Словами: сервер на запрос GET /hello?name=Аня достаёт из запроса метод, путь и параметр name, а затем формирует ответ — ставит код 200, заголовок Content-Type и отправляет JSON.

5. Тестирование через AJAX (XMLHttpRequest / Fetch)
    Это третья часть вопроса — как проверить сервер из браузера, не перезагружая страницу. Используется AJAX (билет 9): асинхронный запрос к серверу из JavaScript.Два инструмента:XMLHttpRequest (XHR) — встроенный объект браузера: open() настраивает запрос, send() отправляет, ответ ловится на стадии readyState === 4 (билет 9).Fetch — современная замена XHR; fetch(url) возвращает Promise, что короче и удобнее:jsfetch('/hello?name=Аня')
        .then(response => response.json())   // разбираем JSON-ответ
        .then(data => console.log(data.message));   // используем данные
    Словами: со страницы через fetch (или XHR) отправляем запрос на сервер, получаем ответ асинхронно (страница не перезагружается), разбираем JSON и выводим результат. Это и есть тестирование сервера средствами AJAX.









//3. Пакет Express. Основные принципы работы. Переадресация. Пример(POSTMAN).

Express — это фреймворк (пакет npm) для Node.js, который упрощает создание веб-сервера. Если на голом модуле http маршрутизацию и разбор запроса приходится писать руками, то Express даёт это «из коробки».

Промежуточное ПО (Middleware) — это функции, которые имеют доступ к объекту запроса (req), объекту ответа (res) и следующей функции промежуточного ПО в цикле "запрос-ответ" приложения. Следующая функция промежуточного ПО обычно обозначается переменной next.

Основные принципы работы (по лекции):
    - Подключение и запуск. 
        Подключается через require('express'),
        создаётся приложение const app = express(), 
        запускается методом app.listen(порт). 
        Остановка — server.close().
    - Маршрутизация (routing). 
        Каждому HTTP-методу соответствует свой метод приложения: app.get(), app.post(), app.put(), app.delete(). 
        В них указывается путь и функция-обработчик. То есть маршрут = метод + путь + обработчик.
    - Объекты request и response. 
        В обработчик передаются два объекта: 
            request (запрос — со своими свойствами и методами, например req.query)
            response (ответ — методы res.send(), res.end() и др.). 
        Через них читают запрос и формируют ответ.
    - Middleware и конвейер. 
        Главный принцип Express — обработка запроса идёт через конвейер из middleware (промежуточных обработчиков). 
        Каждый middleware получает request, response и функцию next; сделав свою работу, он вызывает next(), передавая запрос следующему звену. 
        Это позволяет разбить обработку на independent модули (логирование, аутентификация и т.д.).

Переадресация (redirect) — это когда сервер в ответ на запрос говорит клиенту: «нужного тебе ресурса здесь нет, иди по другому адресу». Браузер получает такой ответ и автоматически переходит на новый адрес.
    Вспомни механизм из билета 5 (структура HTTP-ответа, коды 3xx):
        - сервер возвращает код состояния 3xx (301, 302 и др.);
        - и заголовок Location с новым адресом;
        - браузер видит это и сам делает запрос на адрес из Location.
    То есть Express-переадресация — это удобная обёртка, которая формирует именно такой ответ (код 3xx + заголовок Location).
    Временный и постоянный редирект (это спросят)
    Из билета 5 помни деление:
        - 302 Found — временная переадресация (ресурс временно по другому адресу);
        - 301 Moved Permanently — постоянная переадресация (ресурс переехал навсегда, браузеры это запоминают и кешируют).



    В Express: 
        метод res.redirect(): res.redirect('/new') — редирект 302; 
        res.redirect(301, '/new') — постоянный 301. 
    Express сам подставляет код состояния и заголовок Location.
    Пример: запрос /old → res.redirect('/new') → ответ 302 + Location: /new → браузер переходит на /new.»
