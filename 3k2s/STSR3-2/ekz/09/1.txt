//1. Объект XMLHTTPRequest: определение, назначение

Сначала контекст — AJAX. XMLHttpRequest невозможно объяснить без понятия AJAX, поэтому начни с него.
AJAX (Asynchronous JavaScript and XML) — это подход (методология) построения динамических приложений, основанный на асинхронных запросах, при которых не происходит полной перезагрузки HTML-страницы. То есть страница обновляет только нужную часть, не перезагружаясь целиком. AJAX опирается на три вещи: XMLHttpRequest, DOM и форматы данных XML/JSON.
Синхронный и асинхронный запрос — в чём разница:
    - Синхронный запрос — поток, выдавший запрос, блокируется и ждёт ответа (всё «зависает» до результата).
    - Асинхронный запрос — поток не блокируется; он отправил «заявку» и работает дальше, а для обработки ответа используется функция обратного вызова (callback).

XMLHttpRequest — определение
XMLHttpRequest (XHR) — это встроенный в браузер объект, который даёт возможность делать HTTP-запросы к серверу без перезагрузки страницы. Важно: он существует только в браузере (это часть Browser API, не язык JS сам по себе).
Назначение. Реализовать асинхронный обмен с сервером — отправить запрос и получить данные «на фоне», обновив только часть страницы. Это и есть техническая основа AJAX.

Чтобы сделать запрос к серверу, объект XHR проходит два шага:
    Шаг 1 — open() — подготовить запрос. Ты говоришь объекту: «вот метод (GET/POST), вот адрес, и делай это асинхронно». Запрос пока не отправлен, только настроен.
    Шаг 2 — send() — собственно отправить запрос на сервер.
После send() браузер не «замирает». Запрос ушёл, а страница продолжает работать. Ответ придёт позже.

А как поймать ответ?
Вот тут вступают readyState и onreadystatechange
- readyState — это «индикатор стадии» запроса. Запрос проходит несколько состояний по пути: 
        0 — UNSENT. Объект XMLHttpRequest только что создан, но метод open() ещё не вызывали. Это самое начало: взяла телефон в руки, но номер ещё не набрала.
        1 — OPENED. Вызвали open() — запрос настроен (указали метод и адрес), но ещё не отправлен. Это как набрала номер и сформулировала заказ, но пока не дозвонилась.
        2 — HEADERS_RECEIVED. Вызвали send(), запрос ушёл, и от сервера уже пришли заголовки и статус-код ответа. По аналогии: дозвонилась, ресторан подтвердил «заказ принят».
        3 — LOADING. Идёт загрузка ответа, данные приходят частями — в responseText лежит уже часть данных, но ещё не всё. Это как еда готовится, и тебе по кусочкам говорят, что уже готово.
        4 — DONE. Операция полностью завершена, весь ответ получен. Перезвонили: «всё готово, забирай».
    Каждой стадии соответствует число, и финальная стадия (запрос полностью выполнен, ответ пришёл) — это состояние 4.
- onreadystatechange — сюда ты заранее кладёшь функцию-реакцию (тот самый callback). Браузер вызывает её каждый раз, когда меняется стадия. Внутри функции ты проверяешь: «а стадия уже 4? Если да — значит ответ пришёл, можно с ним работать».

Что такое Callback? — это функция, которая передается в другую функцию в качестве аргумента и вызывается после выполнения определенных операций или событий.


Fetch — современная замена (если уточнят)
Fetch API — более современный и гибкий способ делать сетевые запросы в браузере. Метод fetch(url, options) встроен в браузер и возвращает Promise. По сути Fetch содержит в себе XMLHttpRequest, но удобнее.
Promise — это JS-объект, представляющий асинхронную операцию и её результат.
Форматы данных: JSON (текстовый формат обмена на основе JS-объектов) и XML (расширяемый язык разметки).


//3. Пакет Express. Основные принципы работы. Применение объекта Session для сохранение состояния. Пример (POSTMAN).

Express — это фреймворк (пакет npm) для Node.js, который упрощает создание веб-сервера. Если на голом модуле http маршрутизацию и разбор запроса приходится писать руками, то Express даёт это «из коробки».

Промежуточное ПО (Middleware) — это функции, которые имеют доступ к объекту запроса (req), объекту ответа (res) и следующей функции промежуточного ПО в цикле "запрос-ответ" приложения. Следующая функция промежуточного ПО обычно обозначается переменной next.

Основные принципы работы (по лекции):
    - Подключение и запуск. 
        Подключается через require('express'),
        создаётся приложение const app = express(), 
        запускается методом app.listen(порт). 
        Остановка — server.close().
    - Маршрутизация (routing). 
        Каждому HTTP-методу соответствует свой метод приложения: app.get(), app.post(), app.put(), app.delete(). 
        В них указывается путь и функция-обработчик. То есть маршрут = метод + путь + обработчик.
    - Объекты request и response. 
        В обработчик передаются два объекта: 
            request (запрос — со своими свойствами и методами, например req.query)
            response (ответ — методы res.send(), res.end() и др.). 
        Через них читают запрос и формируют ответ.
    - Middleware и конвейер. 
        Главный принцип Express — обработка запроса идёт через конвейер из middleware (промежуточных обработчиков). 
        Каждый middleware получает request, response и функцию next; сделав свою работу, он вызывает next(), передавая запрос следующему звену. 
        Это позволяет разбить обработку на independent модули (логирование, аутентификация и т.д.).

Применение объекта Session для сохранение состояния
    HTTP не запоминает состояние — каждый запрос для сервера как новый незнакомец. Cookie решали это, храня данные на клиенте. Session (сессия) решает ту же задачу, но хранит данные на сервере — это надёжнее и безопаснее (клиент не видит и не может подменить содержимое).
    
    Как session работает (это ключевое)
    Session использует cookie, но хитро — в этом вся суть:
        - Когда пользователь впервые обращается, сервер создаёт сессию — хранилище данных на сервере — и присваивает ей уникальный идентификатор (Session ID).
        - Этот Session ID отправляется клиенту в cookie (в Express она называется connect.sid).
        - Сами данные (имя пользователя, корзина и т.д.) лежат на сервере, а у клиента в cookie — только «номерок» (Session ID).
        - При каждом следующем запросе браузер автоматически шлёт этот Session ID, сервер по нему находит нужную сессию и «узнаёт» пользователя.

    Сравнение в одну фразу: cookie хранит сами данные на клиенте, а session хранит данные на сервере, а клиенту даёт только идентификатор (Session ID) в cookie.

    Реализация: пакет express-session подключается как middleware (app.use(session({...}))). Дальше через объект req.session: req.session.x = ... (записать), req.session.x (прочитать), req.session.destroy() (удалить, например при выходе).»
