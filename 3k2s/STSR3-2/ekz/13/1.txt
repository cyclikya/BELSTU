//1. RPC: определение, назначение, реализация. 

RPC (Remote Procedure Call) — технология удалённого вызова процедур: позволяет приложению вызвать функцию или метод, находящийся на другом компьютере в сети, так же, как локальную функцию.

Назначение
RPC используется для взаимодействия между распределёнными приложениями. Основные задачи:
    - взаимодействие клиент-серверных приложений;
    - обмен данными между микросервисами;
    - удалённый доступ к функциональности сервера;
    - распределённые вычисления.

Преимущества: простота (вызываешь удалённое как локальное), скрытие деталей сети.
Недостатки: зависимость от сети, задержки, возможны ошибки связи, сложнее отлаживать, чем локальные вызовы.

Реализация — как это работает под капотом
Тут ключевые понятия — Stub (заместитель) и сериализация. Идея: раз по сети нельзя передать «живой вызов функции», его надо упаковать в байты, переслать, распаковать и выполнить. Этим занимаются «заглушки»-посредники.
Главные компоненты:
    - Client (клиент) — инициирует вызов удалённой процедуры.
    - Client Stub — локальный заместитель удалённого метода на стороне клиента. Он упаковывает параметры (это называется marshalling / сериализация — превращение данных в поток байтов для передачи по сети) и отправляет запрос.
    - Server Stub — на стороне сервера принимает запрос и распаковывает параметры (десериализация).
    - Server (сервер) — выполняет саму процедуру и возвращает результат.

Этапы вызова (по шагам):
клиент вызывает функцию;
    - Client Stub сериализует (упаковывает) параметры;
    - запрос уходит по сети;
    - сервер принимает запрос;
    - Server Stub десериализует (распаковывает) параметры;
    - вызывается нужная процедура;
    - результат сериализуется;
    - ответ отправляется клиенту;
    - клиент получает результат.

Цепочка вкратце: Client → Client Stub → (сеть) → Server Stub → Procedure и обратно.
