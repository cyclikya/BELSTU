//1. HTTP-заголовки: классификация, назначение, примеры.

Заголовки HTTP позволяют клиенту и серверу отправлять дополнительную информацию с HTTP запросом или ответом. Они сопровождают обмен данными по протоколу HTTP. Они могут содержать описание данных и информацию, необходимую для взаимодействия между клиентом и сервером. Заголовки и их статусы перечислены в реестре IANA, который постоянно обновляется.
Виды заголовков:
• General: общие заголовки, используются в запросах и ответах;
    - Cache-Control правила кэширования
    - Transfer-Encoding способ передачи данных
    - Date	дата и время сообщения
    - Connection управление соединением

• Request: содержит больше информации о ресурсе, который нужно получить, или о клиенте, запрашивающем ресурс.
    - Host	Имя сервера
    - User-Agent	Информация о браузере/клиенте
    - Accept	Какие типы данных клиент готов принять
    - Authorization	Данные авторизации

• Response: содержат дополнительную информацию об ответе, например его местонахождение, или о сервере, предоставившем его.
    - Server	информация о сервере
    - Location	url редиректа
    - Set-Cookie	установка куки
    - WWW-Authorizate	инструкция по авторизации

• Entity: содержат информацию о теле ресурса, например его длину содержимого или тип MIME.
    - Content-Type	Тип содержимого
    - Content-Length	Размер тела
    - Content-Encoding	Сжатие (gzip)
    - Content-Language	Язык содержимого

• custom:
    Заголовок, который ты создаёшь сама. 
    Это не стандартный заголовок, а собственный — клиент и сервер договариваются о нём сами.


Кеширование – процесс перемещения данных из медленнодействующей памяти в более быстродействующую для повышения производительности.
    Протокол HTTP НЕ ПРЕДУСМАТРИВАЕТ кеширование на стороне сервера, только на стороне клиента !!!
На стороне клиента: Для этого используется заголовок Cache-Control. Это обязывает клиента в соответствии с протоколом кешировать страницу. При следующем обращении (request), клиент будет брать данные из кэша. 
На стороне сервера: нужно кешировать response, поэтому надо его куда-нибудь записать и, когда приходит request, то, если response не устарел, то клиенту можно отдать закешированный сохранённый response.


//3. Разработка клиент-серверного приложения  с применением технологии WebAssembly на стороне браузера. 

WebAssembly (сокращённо WASM) — это низкоуровневый бинарный формат кода, который выполняется в браузере почти со скоростью нативного кода.

Главная идея и проблема, которую он решает: в браузере единственный язык — JavaScript, но он интерпретируемый и для тяжёлых вычислений (графика, обработка видео, игры, математика) медленноват. 
WebAssembly позволяет писать такие тяжёлые части на быстрых языках (C, C++, Rust), компилировать их в бинарный .wasm-модуль и запускать прямо в браузере. JavaScript при этом никуда не девается — он вызывает функции из wasm-модуля.
Ключевые свойства:
    - бинарный формат (компактный, быстро парсится);
    - высокая скорость выполнения (близко к нативной);
    - не замена JavaScript, а дополнение — работают вместе: JS управляет, WASM считает тяжёлое;
    - кроссбраузерность — поддерживается всеми современными браузерами.



На стороне браузера: сервер отдаёт .wasm-файл как статику. В браузере 
JavaScript загружает его: WebAssembly.instantiateStreaming(fetch('/add.wasm'))
скачивает и компилирует модуль, а через instance.exports.add вызывает
экспортированную из модуля функцию. Вычисление выполняет WASM, а не JS.»
