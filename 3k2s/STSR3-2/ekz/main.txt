//1 Интернет: определение, основные составляющие. 
    Сервер – программное обеспечение, которое принимает и обрабатывает запросы.
    Интернет – всемирная сеть, построенная на стеке протоколов TCP/IP.

    Интернет – 4 компонента:
    1.	Стек протоколов TCP-IP — это основа Интернета.
    2.	Интернет-службы (DNS, DHCP, SMTP, POP3 и т.д.).
        ○ Internet-служба: другое название Internet-сервис, один из видов Internet-ресурса, имеющий специальное назначение (DNS, WWW, E-mail, FTP, ICQ, Telnet). Сервер + протокол. Стандартные серверы, которые прослушивают стандартные порты (от 0 до 1024).
        ○ Internet-ресурс: сущность в сети Internet, имеющая адрес (опубликованная в Internet сущность).
    3.	Документация в формате RFC и STD.
    4.	Система организаций, которые поддерживают сеть (в порядке убывания важности, как сказал Смелов):
        ○ ISOC (развитие, внедрение и распространение новых интернет-технологий)
        ○ IETF (разрабатывает стандарты интернета в RFC)
        ○ IAB (занимается архитектурой)
        ○ ICANN (распространяет доменные имена)
        ○ IANA (регистрирует MIME)
        ○ W3C (WWW Consortium, некоммерческая организация для согласования стандартов) — согласовывают всё, что касается веб-программирования (HTTP, CSS, SVG, URI/URL, XML, PNG, JPEG, …). Также они изготавливают стандарты и регистрируют их в IETF.

//1 Web-приложение: определение, принципы устройства.
    Web-приложение — это клиент-серверное приложение, в котором клиент взаимодействует с сервером по прикладному протоколу HTTP.

    Принцип 1. Клиент-серверная архитектура.
    Приложение состоит из двух компонент — клиента и сервера. Это не две половины одной программы на одном устройстве, а две отдельные стороны, которые обмениваются сообщениями.
    Клиент — сторона, которая запрашивает (например, браузер).
    Сервер — обеспечение, которое принимает и обрабатывает запросы, и отвечает на них.
    Web-приложение — это частный случай клиент-серверного приложения: оно становится именно «web», когда клиент и сервер общаются по HTTP. Если бы они общались по другому протоколу — это было бы клиент-серверное приложение, но не web.

    Принцип 2. Взаимодействие строго по протоколу HTTP.
    CORS — это механизм на основе HTTP-заголовков, который позволяет браузеру решать, можно ли коду с одного домена (origin) обращаться к серверу на другом домене. Сервер через заголовок Access-Control-Allow-Origin сообщает, кому разрешено, а браузер на основе этого пропускает или блокирует запрос.

    Принцип 3. Разработка делится на frontend и backend.
    Когда говорят о создании web-приложения, говорят о двух частях:
    frontend — это клиентская часть (то, что выполняется у пользователя, в браузере);
    backend — серверная часть (то, что выполняется на сервере, обрабатывает запросы).
    Это прямое следствие клиент-серверной архитектуры: раз есть две стороны, то и разработка делится на две части.

    Принцип 4. Соединение всегда инициирует клиент.
    Чтобы клиент и сервер обменялись данными, между ними должно быть установлено соединение. И здесь важное правило: инициатором соединения всегда является клиент. Сервер сам не «звонит» клиенту — он ждёт, пока к нему обратятся, принимает запрос и отвечает.

    Принцип 5. Модель «запрос — ответ» (request / response).
    Общение построено на двух типах сообщений:
    request (запрос) — идёт от клиента к серверу;
    response (ответ) — идёт от сервера к клиенту.
    Жёсткое правило: на один request всегда один response. Не бывает запроса без ответа и ответа без запроса — иначе это ошибка. Сервер не отправляет данные по своей инициативе, только в ответ на обращение.

    Принцип 6. Web-приложение состоит из web-ресурсов.
    Web-ресурс — это сущность на стороне сервера, у которой есть адрес (URL/URI) и к которой можно сделать HTTP-запрос и получить HTTP-ответ. Одно web-приложение представлено одним или несколькими ресурсами. То есть, по сути, обращаясь к web-приложению, клиент обращается к его ресурсам по их адресам.
    Связанная деталь (если уточнят): за разграничение доступа между разными доменами в браузере отвечает механизм CORS — он через специальные HTTP-заголовки решает, можно ли клиенту с одного домена обращаться к серверу на другом.

    CORS — это механизм на основе HTTP-заголовков, который позволяет браузеру решать, можно ли коду с одного домена (origin) обращаться к серверу на другом домене. Сервер через заголовок Access-Control-Allow-Origin сообщает, кому разрешено, а браузер на основе этого пропускает или блокирует запрос.

//1 Протокол HTTP: общие свойства, версии и их особенности.
    Создатель HTTP и HTML – Тим Бёрнерс-Ли (Также он глава W3C).

    HTTP – полудуплексный протокол прикладного уровня по кот общаются клиент и сервер, он описывает правила общения

    Версии HTTP:
        3. 1.1 (Действующая версия. Имеет постоянное соединение (Connection: keep-alive), есть SSL/TLS, chunked responses)
        4. 2.0 (Не распространен. Есть параллельные запросы в рамках одного соединения и сжатие одинаковых заголовков. Бинарный: (это значит, что в 2.0 всё изначально закодировано и сжато, а в 1.1 изначально всё в строковом значении, а только потом сжимается))

    HTTP: основные свойства
    - версии HTTP/1.1 – действующий (текстовый), HTTP/2 – черновой (не распространен, бинарный);
    - два типа абонентов: клиент и сервер;
    - два типа сообщений: request и response;
    - от клиента к серверу – request;
    - от сервера к клиенту – response;
    - на один request всегда один response, иначе ошибка;
    - одному response всегда один request, иначе ошибка;
    - TCP-порты: 80, 443(HTTPS);
    - для адресации используется URI или URN;
    - поддерживается W3C, описан в нескольких RFC.
    - HTTP:  RFC2616

    HTTPS (HTTP + SSL/TLS) – специальный протокол, обеспечивающий шифрование и аутентификацию.
    SSL – Secure Socket Layer, был заменен в 2014 на TLS
    TLS – Transport Layer Security
    
//1 Структура HTTP-запроса.
    HTTP-запрос (request) — это текстовое сообщение, которое клиент отправляет серверу. У него есть строгая структура из нескольких частей, идущих в определённом порядке

    Из чего состоит запрос
    1. Стартовая строка (request line). Самая первая строка запроса. Состоит из трёх элементов:
        метод + URI + версия протокола
        Пример: GET /smelov HTTP/1.1
            GET — метод (что хотим сделать),
            /smelov — URI (адрес ресурса, к которому обращаемся),
            HTTP/1.1 — версия протокола.
        Это «шапка» запроса — по ней сервер сразу понимает, что от него хотят и по какому адресу.
    2. Заголовки (headers). Идут после стартовой строки. Это набор пар (имя: значение), которые несут метаинформацию о запросе — например, какой формат данных ожидается, какой хост, какие cookie и т.д. Заголовков может быть много.
    3. Параметры: Отдельный важный момент — параметры запроса можно передавать тремя способами:
            В query string — после знака ? в адресе: /parameter?x=1&y=2. Пары имя=значение.
            В самом URI (в пути) — параметры встроены прямо в путь: /parameter/1/2.
            В теле запроса — данные лежат в body (характерно для POST/PUT).
        То есть один и тот же параметр можно передать по-разному, и сервер достаёт его из нужного места в зависимости от способа.
    3. Тело запроса (body). Это сами данные, которые клиент передаёт серверу. Тело есть не у всех запросов: например, у GET его обычно нет, а у POST и PUT именно в теле едут передаваемые данные (например, JSON или содержимое формы).

//1. Структура HTTP-ответа.
    HTTP-ответ (response) — это сообщение, которое сервер отправляет клиенту в ответ на запрос. Структура очень похожа на запрос, но с одним отличием в первой строке: вместо метода и URI там код состояния. Разберём по частям.

    Из чего состоит ответ
    1. Стартовая строка (status line). Первая строка ответа. Состоит из трёх элементов:
        версия протокола + код состояния + пояснение к коду
        Пример: HTTP/1.1 404 Not Found
            HTTP/1.1 — версия протокола,
            404 — код состояния (число),
            Not Found — пояснение к коду (текстовая расшифровка).
    2. Заголовки (headers). Как и в запросе — пары имя: значение с метаинформацией об ответе (формат данных, длина, дата, cookie и т.д.).
    3. Тело ответа (body). Сами данные, которые сервер возвращает клиенту — например, HTML-страница, JSON, картинка.

    Response: Код состояния:
    -	1xx: информационные сообщения;
    -	2xx: успешный ответ;
    -	3xx: переадресация;
    -	4xx: ошибка клиента;
    -	5xx: ошибка сервера.

//1. HTTP-заголовки: классификация, назначение, примеры.
    Заголовки HTTP позволяют клиенту и серверу отправлять дополнительную информацию с HTTP запросом или ответом. Они сопровождают обмен данными по протоколу HTTP. Они могут содержать описание данных и информацию, необходимую для взаимодействия между клиентом и сервером. Заголовки и их статусы перечислены в реестре IANA, который постоянно обновляется.
    Виды заголовков:
    • General: общие заголовки, используются в запросах и ответах;
        - Cache-Control правила кэширования
        - Transfer-Encoding способ передачи данных
        - Date	дата и время сообщения
        - Connection управление соединением

    • Request: содержит больше информации о ресурсе, который нужно получить, или о клиенте, запрашивающем ресурс.
        - Host	Имя сервера
        - User-Agent	Информация о браузере/клиенте
        - Accept	Какие типы данных клиент готов принять
        - Authorization	Данные авторизации

    • Response: содержат дополнительную информацию об ответе, например его местонахождение, или о сервере, предоставившем его.
        - Server	информация о сервере
        - Location	url редиректа
        - Set-Cookie	установка куки
        - WWW-Authorizate	инструкция по авторизации

    • Entity: содержат информацию о теле ресурса, например его длину содержимого или тип MIME.
        - Content-Type	Тип содержимого
        - Content-Length	Размер тела
        - Content-Encoding	Сжатие (gzip)
        - Content-Language	Язык содержимого

    • Custom:
        Заголовок, который ты создаёшь сама. 
        Это не стандартный заголовок, а собственный — клиент и сервер договариваются о нём сами.

//1. Cookie: определение, назначение, параметры. Фрагмент данных (4 KB), который запоминается клиентом по указанию сервера.
