//1. HTTPS: TLS (основные понятия, процедура handshake), X509-сертификат.  

 HTTPS — это расширение HTTP, обеспечивающее защиту передачи данных с помощью протокола TLS (Transport Layer Security). Проще: HTTPS = HTTP + TLS.

TLS — протокол, который шифрует данные между клиентом и сервером. (Раньше назывался SSL, в 2014 заменён на TLS.)
Сертификат — электронный документ, который гарантирует, что сервер тот, за кого себя выдаёт (что он безопасный и настоящий).
Набор шифров (cipher suite) — совокупность алгоритмов, которая описывает: как вырабатывается ключ, какое шифрование используется, какой метод хеширования и сжатия. То есть «комплект инструментов» для защиты соединения.

Свойства и назначение TLS
    - Шифрование — использует симметричные и асимметричные алгоритмы, чтобы данные нельзя было перехватить.
    - Аутентификация — проверка подлинности сторон с помощью цифровых сертификатов (клиент убеждается, что сервер настоящий).
    - Целостность данных — механизмы (обычно HMAC) гарантируют, что данные не изменили в пути.
    - Конфиденциальность — данные остаются нечитаемыми для третьих лиц.

X509-сертификат
X509 — это формат представления публичного (открытого) ключа.
Что в нём содержится:
    -Версия,
    -Серия (серийный номер),
    -Алгоритмы,
    -Издатель (кто выдал),
    -Субъект (кому выдан),
    -Срок действия,
    -Открытый ключ,
    -Подпись издателя.

Процедура handshake (рукопожатие TLS 1.2)
Это самая объёмная часть. Главная цель handshake: договориться об алгоритмах, проверить сервер по сертификату и выработать общий секретный ключ, которым потом будут шифровать данные. Не обязательно зубрить все 9 шагов дословно — пойми логику, тогда расскажешь своими словами.
Логика в трёх фазах:
    договорились (кто что умеет) →
    проверили сервер и обменялись секретом →
    переключились на шифрование.

Шаги по порядку:
1. Client Hello. Клиент шлёт (в открытом виде): 
    - максимальную версию TLS, 
    - случайное число клиента (32 байта),
    - список поддерживаемых наборов алгоритмов. 
    Смысл: «вот с чем я умею работать».
2. Server Hello. Сервер отвечает: 
    - фиксирует версию, 
    - шлёт случайное число сервера (32 байта)
    - выбирает один набор алгоритмов из списка клиента. 
    Смысл: «договорились, работаем вот так».
3. Certificate. 
    - Сервер присылает свой X509-сертификат (цепочку доверия). 
    - Клиент проверяет: подпись, цепочку до доверенного центра, срок действия, совпадение домена. 
    Смысл: клиент убеждается, что подключился к нужному серверу, и берёт из сертификата открытый ключ.
4. Server Hello Done. Пустое сообщение: «сервер закончил свою часть».
5. Client Key Exchange. 
    - Клиент генерирует предварительный секрет (48 байт), 
    - шифрует его открытым ключом сервера (RSA) и отправляет. 
    - Прочитать сможет только сервер (своим закрытым ключом). 
    Смысл: обе стороны теперь имеют общий секрет, который никто не перехватил.
Вывод ключей (между 5 и 6). Из предварительного секрета + двух случайных чисел обе стороны независимо вычисляют главный секрет, а из него — рабочие ключи шифрования. Считают это сами, по сети не передают.
6. Change Cipher Spec (клиент). Клиент шлёт сигнал: «дальше шифрую». 
    Это граница между открытой и зашифрованной фазой.
7. Finished (клиент). 
    Первое зашифрованное сообщение — проверочный хеш всех предыдущих сообщений. 
    Подтверждает, что ключи вывели правильно и переписку не подменяли.
8. Change Cipher Spec (сервер). Сервер тоже переключается на шифрование.
9. Finished (сервер). Зашифрованное проверочное сообщение от сервера. Если клиент проверил и всё сошлось — рукопожатие завершено, дальше идут зашифрованные прикладные данные.
