## 🎯 ДЕТАЛЬНОЕ ОПИСАНИЕ КАЖДОГО ЗАДАНИЯ

### 11-1: Загрузка файла на сервер
**Суть:** Клиент отправляет локальный файл на сервер, который сохраняет его в папку `upload`.

**Как работает:**
1. Клиент запрашивает путь к файлу у пользователя
2. Читает файл потоком (chunks) и отправляет бинарные данные
3. Сначала отправляет имя файла (текст), затем бинарные фрагменты
4. При закрытии соединения сервер собирает все фрагменты и сохраняет файл

**Ключевые особенности:**
- Потоковая передача (эффективно для больших файлов)
- Бинарные данные в WebSocket (`{ binary: true }`)
- Буферизация на серверной стороне

**Команда запуска:**
```bash
# Сервер
node s-11-1.js

# Клиент (в отдельном окне)
node c-11-1.js
```

### 11-2: Скачивание файла с сервера
**Суть:** Клиент запрашивает файл по имени, сервер отправляет его потоком.

**Как работает:**
1. Клиент вводит имя файла для скачивания
2. Отправляет имя файла на сервер через WebSocket
3. Сервер ищет файл в папке `download`
4. Если найден - создаёт поток чтения и отправляет через WebSocket
5. Клиент получает данные и сохраняет в локальный файл

**Ключевые особенности:**
- Использование `createWebSocketStream()` для потоковой передачи
- `.pipe()` для эффективного перенаправления потока
- Обработка ошибки "файл не найден"

**Команда запуска:**
```bash
# Сервер
node s-11-2.js

# Клиент
node c-11-2.js
```

### 11-3: Ping/Pong и периодические сообщения
**Суть:** Демонстрация механизма проверки живости соединения и регулярной отправки сообщений.

**Как работает:**
1. Сервер каждые **5 секунд** отправляет `ping` всем подключённым клиентам
2. Клиент получает ping и автоматически отвечает `pong`
3. Сервер каждые **15 секунд** отправляет счётчик всем клиентам
4. Клиент выводит полученные сообщения в консоль

**Ключевые особенности:**
- `ws.ping()` и `ws.pong()` - встроенные методы WebSocket для проверки соединения
- Отслеживание активных клиентов
- `setInterval()` для периодических операций
- Проверка состояния соединения перед отправкой (`readyState === WebSocket.OPEN`)

**Команда запуска:**
```bash
# Сервер
node s-11-3.js

# Клиент (можно несколько одновременно)
node c-11-3.js
```

### 11-4: JSON-RPC обмен данными
**Суть:** Простой обмен JSON-сообщениями между клиентом и сервером с подсчётом.

**Как работает:**
1. Клиент вводит своё имя
2. Отправляет JSON объект на сервер с полями: `client` (имя), `timestamp`
3. Сервер получает сообщение, увеличивает счётчик
4. Отправляет обратно ответ JSON с полями: `server` (номер), `client`, `timestamp`
5. Клиент получает ответ, выводит и закрывает соединение

**Ключевые особенности:**
- `JSON.stringify()` и `JSON.parse()` для сериализации
- Однократный обмен сообщениями
- Использование `timestamp` для синхронизации

**Команда запуска:**
```bash
# Сервер
node s-11-4.js

# Клиент
node c-11-4.js
```

### 11-5: RPC функции с аутентификацией
**Суть:** Реализация удалённого вызова функций на сервере. Некоторые функции защищены и требуют аутентификации.

**Реализованные функции:**

#### Публичные функции (доступны всем):
- **square(r)** или **square(a, b)**: 
  - 1 параметр → площадь круга (π·r²)
  - 2 параметра → площадь прямоугольника (a·b)
  
- **sum(...args)**: сумма всех параметров
  
- **mul(...args)**: произведение всех параметров
  
- **mod(a, b)**: остаток от деления (a % b)
  
- **abs(x)**: абсолютное значение

#### Защищённые функции (требуют аутентификации):
- **fib(n)**: последовательность Фибоначчи до n-го элемента
- **fact(n)**: факториал числа n

**Варианты клиента:**
1. **c-11-5.js** - базовый вызов public функций (без доступа к protected)
2. **c-11-5login.js** - вызов с аутентификацией (логин: `gdv`, пароль: `28`)
3. **c-11-5expression.js** - вычисление сложного выражения через несколько RPC вызовов
4. **c-11-5parallel.js** - параллельные вызовы функций через `Promise.all()`

**Как работает аутентификация:**
```javascript
server.setAuth((credentials) => {
  return (credentials.login === 'gdv' && credentials.password === '28');
});
```

**Команда запуска:**
```bash
# Сервер
node s-11-5.js

# Клиент (выбрать один вариант)
node c-11-5.js           # только public функции; protected недоступны без логина
node c-11-5login.js      # с логином
node c-11-5expression.js # вычисление выражения
node c-11-5parallel.js   # параллельные вызовы
```

### 11-6: События (Events) и подписка
**Суть:** Демонстрация паттерна "издатель-подписчик" через WebSocket RPC.

**Как работает:**
1. Сервер определяет события: **A**, **B**, **C**
2. Клиент подписывается на интересующее его событие
3. Сервер в интерактивном режиме отправляет события (через stdin)
4. Все подписчики получают уведомление в режиме реального времени

**Варианты клиента:**
- **c-11-6a.js** - подписывается на событие A
- **c-11-6b.js** - подписывается на событие B
- **c-11-6c.js** - подписывается на событие C

**Команда запуска:**
```bash
# Сервер (в режиме ввода команд)
node s-11-6.js
# Вводить: A, B или C

# Клиенты (в отдельных окнах)
node c-11-6a.js  # слушает A
node c-11-6b.js  # слушает B
node c-11-6c.js  # слушает C
```

### 11-7: Интерактивные команды
**Суть:** Интерактивный клиент, который отправляет команды на сервер через stdin.

**Как работает:**
1. Клиент подключается к серверу
2. Пользователь вводит команду (A, B или C) в интерфейс клиента
3. Клиент отправляет команду на сервер через `notify()`
4. Сервер получает команду и может выполнить её

**Отличие от 11-6:**
- В 11-6: сервер отправляет события, клиенты слушают
- В 11-7: клиент отправляет команды, сервер их получает (обратное направление)

**Команда запуска:**
```bash
# Сервер
node s-11-7.js

# Клиент (в отдельном окне)
node c-11-7.js
# Вводить: A, B или C
```

## 🚀 ЗАПУСК ЕДИНОГО СЕРВЕРА

**Этот сервер запускает на разных портах:**
- **Порт 4000** - RPC функции (задания 3, 5)
- **Порт 4001** - WebSocket загрузка файлов (задание 1)
- **Порт 4002** - WebSocket скачивание файлов (задание 2)
- **Порт 4003** - JSON-RPC обмен (задание 4)
- **Порт 5000** - RPC события и команды (задания 6, 7)

**Затем в отдельных окнах можно запускать всех клиентов одновременно!**
